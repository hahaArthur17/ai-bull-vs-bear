# Web 作品版开发总计划

创建：2026-11-04；更新：2026-11-05（Pacific/Auckland）。状态：Web Demo 已实现并公开发布，验证范围和未完成项见进度文档；结果见[开发进度](progress.md)。

## 1. 产品目标与交付边界

把 AI Bull vs Bear 做成可公开访问的浏览器作品，优先展示前端的设计、组件、状态、异步请求、表单、可访问性和交付能力。保留现有手机端及后端，为未来 Full Stack 求职提供基础。

首个作品版本采用明确标识的 Demo 研究数据：访客无需注册即可搜索股票、查看图表、回放辩论、查阅证据、管理收藏和历史，并从用户页下部进入用户反馈表单。反馈用于收集对应用的建议或问题，最终支持后端接收，不是研究资料或开户表单。

研究数据与反馈接收分别配置：首轮反馈也可演示；真实反馈接收作为独立小后端里程碑，不必等待全部 Full Stack 模块完成。研究数据为 Demo 时，仍可在明确启用真实反馈模式后把用户意见送到后端。

本文件保留开发路线与验收标准。具体完成状态以文末清单及开发进度为准，不能将阶段计划直接当作测试或发布结果。

## 3. 首版范围

### 页面与路由

| 路由 | 页面 | 首版职责 |
| --- | --- | --- |
| `/` | Research Workspace | 搜索、筛选、收藏列表、研究入口 |
| `/stocks/:ticker` | Stock Research | 报价摘要、区间图表、指标、证据和辩论入口 |
| `/debates/:sessionId` | Debate Room | Bull/Bear/Judge、脚本回放、暂停继续、引用与总结 |
| `/history` | Research History | 搜索、筛选、重新打开；Demo 本地记录可确认删除 |
| `/user` | User Center | 本地偏好、体验概况；下滑后显示反馈入口按钮 |
| `/feedback` | Send Feedback | 建议/问题分类、标题、描述、联系信息、附件和提交回执 |
| `/about` | About This Project | 能力展示、设计取舍、Demo 边界、源码入口 |
| 未匹配路径 | Not Found | 解释无效地址并提供返回入口 |

证据详情首版使用侧栏/弹窗，允许 URL 查询参数保存选中的证据；不额外扩展成复杂独立平台。图表区间、搜索条件等有分享价值的状态进入 URL。

### 两条主流程

1. 搜索股票 → 打开研究页 → 切换图表 → 开始演示辩论 → 查看引用 → 历史重开。
2. 打开用户页 → 向下滚动到反馈区 → 点击 `Send feedback` → 填写意见或预填合成示例 → 选择附件 → 校验 → 提交 → 查看编号与结果 → 返回用户页原位置。

首轮 Demo 不承诺真实行情、实时模型、多人数据同步、真实附件存储或邮件发送。反馈演示回执不表示作者已经收到；只有真实反馈接收阶段完成后才显示服务器已接收。Demo 的暂停继续是演示回放控制，不等同于真实后端的生成中断接口。

## 4. 技术选择

| 层 | 选择 | 原因与限制 |
| --- | --- | --- |
| 应用 | React + TypeScript + Vite | 适合交互型 SPA，保持现有 React 知识与类型模型 |
| 样式 | Tailwind CSS + shadcn/ui | 使用官方组件源码与语义 token 统一界面 |
| 路由 | React Router Data Mode | 集中路由、错误边界、懒加载；接口缓存交由 Query |
| 接口状态 | TanStack Query + fetch | 缓存、更新与失效；HTTP 错误归一化 |
| 表单 | React Hook Form + Zod | 输入状态、schema、字段错误和提交状态 |
| Demo | MSW + 合成 fixture | 请求经过正常数据访问层，模拟能力与真实契约分离 |
| 图表 | 先评估 shadcn Chart / Recharts | 复用原数学函数；加入数据表/文字摘要和稳定尺寸 |
| 动效 | CSS 优先，必要时 Motion | 为反馈与布局变化服务，提供 reduced motion |
| 验证 | Vitest + Testing Library + Playwright | 纯逻辑、交互状态与关键端到端流程 |

Node 工具链先与现有项目使用的 24 系列对齐，再核对所选 Vite 版本要求。独立 npm 包与锁文件，不把整个仓库同时改造成复杂 monorepo。具体安装版本以 G1 的官方兼容检查和锁文件为准。

## 5. 分阶段执行

### G0：保存原项目与建立开发分支

操作顺序：

1. 复查当前分支、差异与文件归属，区分原有 267 项变化和本轮新增的 `apps/web` 规划。
2. 审阅并保存原有工作，运行与改动相关的现有检查，记录通过、失败和未验证范围。
3. 将原有工作单独提交并推送；不要误提交凭证、真实附件或本地数据库文件。
4. 给原项目检查点命名，例如 `baseline/pre-web-2026-11-04`。标签只记录已提交内容。
5. 从保存后的现有开发线创建 `codex/web-portfolio`，再把 Web 规划与后续实现独立提交。
6. 当前不以旧 `main` 为直接起点，也不为启动 Web 强行合并全部历史；后续另行整理合并策略。

2026-11-05 用户授权实施和逐步提交后，已将原有工作单独保存为 `f804d10`，添加 `baseline/pre-web-2026-11-05`，并建立 `codex/web-portfolio`。该检查点用于保存原工作，不代表旧后端与手机端测试已在本轮重跑。

验收：原项目有可恢复的 commit；远程保存已确认；工作区内容归属明确；Web 分支来源清楚。

### G1：初始化可运行工程

1. 在临时目录生成 React + TypeScript 的 Vite 模板，审阅后迁入，保留已有文档与目录。
2. 创建独立 `package.json`、`package-lock.json`、TS 配置、Vite 配置、ESLint 与 Prettier 配置。
3. 配置 `@/` 指向 `src`，同时覆盖 TypeScript、Vite 和测试环境。
4. 按当前官方 Vite 方案安装 Tailwind 插件，使用 CSS 导入；不混入旧版安装步骤。
5. 在已有项目中初始化 shadcn/ui；选定一套组件底层与 preset 并记录，按需添加组件源码。
6. 实现入口、路由、Provider、错误边界、环境变量解析，分别配置研究数据与反馈接收模式。
7. 安装 MSW、生成 worker，显式 await 启动完成后再挂载应用。
8. 建立 `dev`、`build`、`preview`、`typecheck`、`lint`、`format:check`、`test`、`test:e2e` 脚本。

验收：首屏可访问；所有空壳路由有明确状态；类型检查与构建通过；生产构建中的 Demo 请求也能被正确模拟。

### G2：设计系统与应用框架

1. 以股票详情页为视觉样板，确定语义颜色、排版、数据密度、间距、圆角和图表规范。
2. 建立侧边导航、顶栏、移动端 Sheet、页面标题、状态反馈与主题选择。
3. 整理 Button、Card、Badge、Tabs、Dialog、Sheet、Field、Skeleton 等基础组件。
4. 检查 360px、768px、1440px；补查 320px、200% 缩放、键盘顺序和触控目标。
5. 为亮色/暗色主题使用同一语义 token，不把业务颜色散落到各页面。

验收：样板页在两种主题及主要尺寸下可读；焦点可见；主内容不意外横向溢出；错误和空数据状态也遵循规范。

### G3：数据访问与可复现场景

1. 以现有 API 的路径、字段和错误语义为参考定义 DTO、查询键、服务函数和 ViewModel。
2. 复用纯类型和算法的可用部分，避免直接导入耦合 Expo 的整份 API 客户端。
3. 创建固定股票/证据/辩论 fixture，覆盖正常、过期、不足、不可用与目录专用数据。
4. 在 MSW handler 中模拟延迟、失败、分页和变更；业务组件不直接读取 fixture。
5. 收藏和演示历史采用版本化本地存储；提供重置，反馈正文、个人联系信息和附件默认只留在内存。
6. 研究 `demo` 与 `api` 使用统一服务接口；反馈使用独立的 `demo/api/disabled` 模式，只拦截显式启用的演示接口。未知模拟 API 明确失败，已配置的真实反馈地址不被误拦截。

验收：正常/空数据/延迟/错误均能重复复现；清空存储后的新访客可完成首条流程；切换模式有明确边界。

### G4：研究工作台与股票详情

1. 搜索防抖、筛选、排序、URL 状态、加载/无结果/重试。
2. 收藏即时反馈、失败回滚、重复点击处理、刷新恢复。
3. 区间图表、指标解释、有效数据缺失展示、证据侧栏。
4. 图表和大模块按需加载，固定占位尺寸，避免切换时页面跳动。

验收：快速切换关键词/股票不会出现旧请求覆盖；深链接刷新可用；图表有文本或数据表替代。

### G5：辩论回放与历史

1. 把消息状态、回放调度、自动跟随和页面渲染分别实现。
2. 回放支持暂停/继续、重新播放和离开页面后的清理。
3. 用户向上阅读时停止强制跟随；允许回到底部；引用能定位原证据。
4. 历史列表支持搜索、筛选、重开与确认删除；删除仅操作本访客的可序列化 Demo 记录。现有后端没有历史删除接口，API 模式的历史先只读，不把本地隐藏包装成服务端删除。
5. 标明预设内容回放；真实 API 模式的事件、重连和中断留到后续集成阶段。

验收：离开后无残留计时器；重复打开无重复消息；历史重开结果一致；演示与真实生成不混淆。

### G6：用户页入口、反馈表单与附件

1. 创建 `/user`，在偏好/体验概况之后的下部区域放置 `Send feedback` 按钮；点击进入 `/feedback`，返回时恢复位置。无需登录即可体验。
2. 按[表单设计](forms-and-uploads.md)完成分类、标题、详细意见、相关页面、条件问题复现、可选体验评分和联系信息，建立 schema 与错误摘要。
3. 保留姓名、邮箱、性别；姓名与性别可选，邮箱在勾选希望收到回复时必填。性别不影响处理顺序。
4. 实现原生文件选择、拖放增强、校验、列表、预览、移除、取消和重试。
5. `VITE_FEEDBACK_MODE=demo` 模拟提交，明确未向作者发送；`api` 只连接已验证的反馈接收后端，尚未提供时使用 `disabled` 或显示配置错误，不伪造送达。

验收：下滑入口和返回位置、条件字段、必填/格式/边界/附件/重复提交/取消/错误恢复/键盘操作全部覆盖；访客输入的意见、联系信息和附件不写入公共 fixture、日志或本地持久化。

### G7：整体验证与作品说明

1. 对关键 schema、算法、状态转换写有意义的单元测试。
2. 对搜索、收藏、辩论跟随、表单错误与附件行为做组件测试。
3. 在构建产物上验证两条完整流程，包括深链接、新访客、错误场景与重置。
4. 测量首屏加载、布局偏移、长任务、图表与消息更新；根据实测定位优化。
5. 补齐 About、数据边界、设计决策、测试结果与后续 Full Stack 接入说明。

验收：检查结果记录具体日期/环境/构建 SHA；不把计划指标写成已经达到的成绩。

### G8：独立部署与正式发布

1. 创建独立 Web 托管项目，构建根目录 `apps/web`、输出 `dist`。
2. 配置显式 Demo 模式、静态资源与 SPA 路由回退；保护 worker 路径。
3. 增加 Web CI job 与预览部署，验收后发布固定作品地址。
4. 在真实公网地址完成首次访问、深链接、附件演示、重置、主题和移动布局冒烟检查。
5. 保留上一可用部署，验证回滚方式，记录正式 URL 和构建 SHA。

详细要求见[部署与发布计划](deployment.md)。当前已发布包含完整 Demo 功能的作品。

### G9A：真实反馈接收闭环

可在其他研究功能仍为 Demo 时单独实施。新增拟议 `POST /feedback`：服务端校验、持久化反馈及必要附件元信息、私有附件存储、限流和重复提交处理；返回真实编号与 `received` 状态。提供作者受保护的后台列表/详情或受限管理查询，能按编号查看意见和附件。接口、存储、权限及实际接收验证通过后，才启用 `VITE_FEEDBACK_MODE=api`。

验收：从公开 Web 提交合成反馈 → 服务端确认 → 作者在受保护入口按编号查到内容/附件 → 服务重启后仍存在。请求失败和取消不显示假送达，不公开访客联系信息。邮件通知/答复为后续选项，不是首个接收闭环的依赖。

### G9B：其他 Full Stack 扩展

使用现有 API 分模块接入真实股票、收藏、认证、分析和辩论；每接一个模块单独验证请求、身份、持久化和异常恢复。真实历史删除作为新增后端需求另行设计，契约完成前不开放 API 模式删除。API 不可用时给出明确状态，不自动切换成假成功。
