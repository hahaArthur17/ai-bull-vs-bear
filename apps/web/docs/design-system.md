# 视觉与交互规范

创建：2026-11-04；更新：2026-11-05。以下为首版设计提议，G2 的股票详情样板页完成后记录实际 token 和截图。

## 1. 视觉方向

以清晰、克制的研究工作台为主：中性背景、明确数据层级、少量市场语义色。保留 Bull/Bear/Judge 的产品识别，让图表、观点和证据成为重点。

桌面首屏优先呈现正在研究的股票、核心指标和下一步操作；避免把所有信息包装成同样大小的卡片。用开放区域、分隔线和少量卡片形成层次。首版 UI 文案使用英文，设计/开发文档使用中文。

默认跟随系统主题，并允许切换亮色和暗色；两种主题共用语义变量。选择偏好可本地保存，首屏尽早应用，减少主题闪烁。

## 2. 设计变量

基于 shadcn/ui 的 CSS 变量扩展，在 `src/styles` 集中管理，Tailwind 类引用语义名称。

| 类别 | 规范提议 |
| --- | --- |
| 表面 | `background`、`card`、`popover`、`muted`；用层次区分，不滥用阴影 |
| 内容 | `foreground`、`muted-foreground`、`primary-foreground` |
| 控件 | `primary`、`secondary`、`accent`、`border`、`input`、`ring`、`destructive` |
| 领域 | `bull` 青绿、`bear` 玫红、`judge` 紫色；同时配文字和图标 |
| 图表 | 主价格线、短/长均线、成交量和参考线分别定义，不与操作按钮混用 |
| 间距 | 4px 基础节奏，常用 8/12/16/24/32/48px |
| 圆角 | 小控件约 6–8px，主要卡片 12px；胶囊只用于合适的标签 |
| 排版 | 正文 16px，辅助文字 13–14px，页面标题约 28–32px；字号随布局调整 |
| 数值 | 价格和指标使用等宽数字；日期/时区/单位有一致格式 |

具体色值在样板页中实测对比度后确定。正文目标至少 4.5:1，大文字/控件边界与状态目标至少 3:1，不能只通过颜色传达涨跌、错误或选中。

## 3. 响应式布局

- 小于 768px：单列，导航收进 Sheet；重要操作靠近相关内容，复杂表格改为明确的滚动区或摘要列表。
- 768–1199px：紧凑导航、主次区域按空间组合，证据侧栏避免挤压图表。
- 1200px 起：完整侧栏、研究主区、可展开证据区。内容最大宽度约 1440px，表单主区保持阅读宽度。
- 主要验收宽度 360/768/1440px，补查 320px 和 200% 缩放。以内容能否阅读操作为准，不只看断点截图。

触控目标以至少 44px 的可操作区域为目标。页面不整体横向滚动；图表、数据表确需横向阅读时只在自身容器内滚动。

## 4. shadcn/ui 使用方式

只引入用到的组件源码，记录初始化 preset 和底层组件选择。业务风格通过 token 和明确 variants 调整，避免在每页重复覆盖一串特殊颜色。

| 场景 | 组件候选 | 项目负责的部分 |
| --- | --- | --- |
| 应用导航 | Sidebar、Sheet、Button、Tooltip | 路由状态、当前页面与窄屏行为 |
| 股票搜索 | Input；需要键盘候选列表时 Command/Combobox | 防抖、请求、无结果、可访问选择 |
| 指标与研究 | Card、Badge、Tabs、Separator | 数据优先级、过期/缺失标识 |
| 证据阅读 | Sheet、Dialog、ScrollArea | 引用定位、返回焦点、来源信息 |
| 反馈 | Skeleton、Alert、Toast、Progress | 状态文案、重试、避免重复播报 |
| 表单 | Field、Input、RadioGroup、Button、AlertDialog | schema、文件队列、提交状态 |
| 图表 | Chart 基础组件与 Recharts | 数据正确性、区间、交互与替代信息 |

这里的表格不是必须全部安装的清单。搜索控件若使用组合方案，要验证所选官方组件的键盘语义；不要把普通输入框包装成不完整的自定义下拉框。

## 5. 各页面呈现

### Research Workspace

页首简短产品说明、搜索框和清晰 Demo 标识。主体为收藏列表及搜索结果；结果显示代码、公司、覆盖能力与收藏按钮。筛选/排序安排在列表上方。空收藏状态引导添加，不填充大量假指标卡片。

### Stock Research

页首为股票信息、覆盖状态、数据时间与研究入口。主区优先价格和区间图表，其次指标解释；证据在侧区或 Sheet 中展开。一次突出一个主要行动“Start demo debate”，不用多个同权重主按钮。

图表保持稳定高度；区间切换、选点与图例不会造成整页跳动。缺失值留空并解释，不画成 0。提供趋势摘要及数据表，不能要求所有访客只通过鼠标悬停阅读。

### Debate Room

角色、轮次、状态和引用分层呈现。Bull/Bear 除颜色外还有文字标签；Judge 总结在适当阶段出现。底部提供清晰的回放控制和“回到最新消息”。右侧证据区在窄屏转为 Sheet。

逐步显示的是预设脚本，始终标为 Demo replay。用户向上滚动时暂停自动跟随；新消息数量可提示但不抢滚动位置。减少动态效果时仍可阅读完整内容。

### Research History

以日期、股票和结果摘要组织条目，保留搜索/筛选。Demo 本地记录的删除使用确认弹窗；API 模式先只读，真实删除待后端提供接口。重新打开后恢复到明确的记录状态。空状态、无搜索结果和加载失败分别处理。

### User Center 与 Send Feedback

`/user` 是访客可打开的用户页，展示本地偏好和体验概况，不伪装已登录账户。按用户要求，在这些内容之后的下部区域放置 `Help improve this app` 区块：简短说明、消息图标和 `Send feedback` 按钮。滚动到此处后点击进入 `/feedback`，不用弹窗突然打断主流程。

反馈页顶部提供 `Back to user page`；返回时恢复到原入口附近，直接访问反馈链接也能返回 `/user`。桌面为宽表单与窄提交说明栏，移动端单列。按“反馈内容 → 附件 → 可选联系信息 → 提交”组织，让意见和相关截图优先呈现。

分类用 Select，标题用 Input，详细意见用 Textarea；选 Bug 时展示复现步骤/预期与实际结果。可选体验评分使用有文字等级的 RadioGroup；希望回复使用 Checkbox，勾选后邮箱必填。姓名和性别可选，性别提供不愿透露。重点为意见本身，不因字段或控件数量影响填写效率。

成功回执与当前模式一致：Demo 显示 `Feedback demo completed — not sent`；真实后端确认后显示 `Feedback received` 和编号。提交失败保留输入并提供重试。字段始终有 label，提示与错误位置稳定。详细规则见[用户反馈设计](forms-and-uploads.md)。

## 6. 动效与反馈

- 按钮反馈约 100–150ms，侧栏/弹窗约 160–220ms；这些是设计默认值，按实测调整。
- 普通过渡优先使用 opacity/transform，不对整个页面应用 `transition-all`。
- 只在真正加载时使用 skeleton；避免为“看起来顺滑”给所有请求强制长延迟。
- 进度条显示可解释的进度，模拟文件处理不得标成已测量的真实上传字节。
- 减少动态效果时取消大幅位移、闪烁和非必要自动动画，保留操作状态反馈。
- 成功通知不能替代页内结果；错误应靠近相关内容并给出恢复入口。

## 7. 可访问性与性能

使用语义化 HTML、真实链接和按钮；键盘焦点可见且顺序合理。弹窗打开后管理焦点，关闭后回到触发处；路由变化更新标题并把阅读位置放到合适的页面起点。

表单字段关联 label/description/error。实时消息与进度采用克制的播报，不能每一帧打断读屏。图表、图标按钮和仅图形状态都有文字说明。

初始工程对路由和图表分包；长消息只更新必要区域，确有性能问题再引入虚拟列表。性能预算提议：部署后实测桌面 Lighthouse performance ≥90、accessibility ≥95，移动端优先检查布局偏移与交互响应；记录测试条件，不将一次实验成绩等同于真实用户指标。

这些是待验证目标，不是当前已达结果。若未达标，先记录瓶颈、修复或解释有依据的取舍。
